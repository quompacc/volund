# Changelog-Archiv

[Zur aktuellen Änderungsübersicht](../../CHANGELOG.md).

## [0.20.0] - 2026-08-29

### Added

- Added an explicit target-library selector to import metadata and require its
  stable public ID before upload review.

### Changed

- OpenAPI now documents collection routes, model tags and collections, selected
  import collections, and the required target-library ID.
- A contract regression test now compares all Axum API paths with the committed
  OpenAPI paths and verifies the recent catalog schema fields.
- Reconfiguring import metadata now invalidates the previous review plan before
  a new target library, file plan, or collection set is accepted.
- PostgreSQL integration tests now hold a cross-process isolation lock and reset
  only explicitly named disposable test or audit databases.

### Fixed

- Import review now searches for reusable and relocatable content only inside
  the selected library instead of falling back to another library's first
  matching source or the globally first root.
- The import-path regression now verifies that an edited model name produces
  the edited slug in the final target directory.

### Documentation

- Added a product contract and phased roadmap covering instance setup, users,
  authorization, settings, administration, the complete engineering catalog
  lifecycle, collaboration, recovery, portability, and integrations.
- Added an honest v0.19.1 maturity inventory so database foundations,
  prototypes, partial workflows, and complete capabilities are not conflated.
- Corrected the stale version and product-completeness language in the project
  overview.
- Recorded a read-only repository and production baseline audit with verified
  quality-gate results, prioritized findings, recovery evidence, and a mandatory
  remediation gate before Phase 1.

## [0.19.1] - 2026-08-29

### Fixed

- Database readiness now expects the collection-import join table introduced by
  migration 0009, so a fully migrated production schema is reported healthy.

## [0.19.0] - 2026-08-29

### Added

- Persistent collection listing and creation APIs with model counts.
- Import-time selection of multiple existing collections and creation of a new
  collection directly from the metadata form.
- Forward migration 0009 retaining collection choices on import drafts until
  their atomic model commit.

### Changed

- Dashboard, model archive, model details, and collection views now use the
  real PostgreSQL catalog instead of static prototype models.
- Model summaries now expose persisted tags and collection names, making both
  visible immediately after import.

### Fixed

- Production web installation instructions now enforce readable root-owned
  assets and verify access as the service account.

## [0.18.0] - 2026-08-29

### Changed

- The browser import now moves directly from metadata into upload and internal
  review, followed by one clear `Importieren` action for the atomic commit.
- Manifest and review file plans are collapsed behind `Details anzeigen` by
  default, while the technical upload-resume fallback lives under unobtrusive
  additional options.
- Import progress uses short user-facing states and offers retry actions for
  interrupted uploads and commits, plus a visible `Modell öffnen` action after
  successful completion.

## [0.17.1] - 2026-08-28

### Fixed

- New staged files are now copied into a synchronized temporary file inside the
  library and atomically published there. This works across systemd's separate
  writable bind mounts while retaining no-overwrite and rollback guarantees.

## [0.17.0] - 2026-08-28

### Added

- Atomic import confirmation revalidates all staged and matched SHA-256 hashes,
  refuses target overwrites, publishes files, preserves relocated source UUIDs,
  attaches all 156 project files to the model, and rolls filesystem changes back
  when persistence fails.
- Import completion persists author, tags, model metadata, source roles, move
  audit records, and a committed timestamp before clearing isolated staging.

### Changed

- The import review now shows the complete file total separately from new,
  relocated, and reused files, with confirmation above the long file plan.

## [0.16.1] - 2026-08-28

### Fixed

- Resuming a production import now casts PostgreSQL's integer file count to the
  API's 64-bit count instead of terminating the request on strict decoding.
- Final target paths no longer retain the draft's initial slug after the model
  name is edited during import review.

## [0.16.0] - 2026-08-28

### Added

- Resumable import review for the newest fully staged draft, including existing
  model detection, content-hash deduplication, target-root selection, stable
  source relocation plans, path-conflict reporting, and persisted decisions.
- Browser review showing new, reused, relocated, and conflicting files plus
  saved bytes and the final proposed raw-file destination.

### Changed

- Autodesk Fusion `.f3d` files are classified as native CAD sources.
- Repeated filename directories such as `part.step/part.step` are collapsed in
  final target proposals without changing the uploaded original manifest.

## [0.15.0] - 2026-08-28

## [0.12.0] - 2026-08-28

### Added

- Clickable model-centric browser prototype with dashboard metrics, model cards,
  model details, interactive lightweight 3D file cards, deferred large-CAD
  loading, supporting documents, and a secure ZIP-import concept.
- Permanent navigation back to the existing live raw-file catalog so the new
