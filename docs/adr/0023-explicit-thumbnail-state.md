# ADR 0023: model thumbnails are explicit catalog state

- Status: Accepted
- Date: 2026-08-30

## Context

Inferring a card image from directory order, the primary CAD source, or the
latest conversion makes presentation unstable. It also lets retention silently
invalidate a user-visible choice and encourages arbitrary filesystem or URL
references.

## Decision

A model stores exactly one of three states: deliberate `default`, an associated
raster `source-file`, or a ready raster `derived-artifact`. The database shape
constraint and foreign keys make invalid combinations impossible. The API derives
candidates from current model relationships, permits PNG, JPEG, GIF, and WebP,
and rejects SVG, missing sources, foreign content, and non-ready artifacts.

Selection is a revisioned model mutation with actor audit. Reads expose one shared
state object containing kind, stable candidate ID, application-owned stream URL,
and `default`, `ready`, or `fallback` status. A missing selected source therefore
degrades visibly without rewriting the user's choice.

Retention excludes conversion runs containing a selected artifact and rechecks
the reference while artifact rows are locked before touching bytes. Source images
remain private/no-cache; derived images retain content-hash ETags and immutable
cache semantics.

## Consequences

No thumbnail bytes are generated by this decision. Existing models migrate to an
intentional default and older binaries ignore the additive columns. Clearing a
selection increments model revision just like choosing one, preventing lost
updates between metadata and presentation editors.
